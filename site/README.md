# mainbus.app

The marketing site for Mainbus: one page of plain HTML and CSS, with no build step, no scripts and no dependencies. Open `site/index.html` in a browser to see it.

**Nothing has been deployed.** No host, DNS record or workflow run has been set up by the agents that made this site. Hosting and the domain are yours to set up, with the steps below.

## What's here

| File | What it is |
|---|---|
| `index.html` | The page. Its links are relative, so it also works opened straight from the file. |
| `404.html` | The not-found page. Its links are root-absolute (`/styles.css`, `/`), because hosts serve it at whatever path was asked for. It has `noindex`. |
| `styles.css` | The styles: the icon's navy, belt and orange (Night Owl), in a light and a dark scheme that follow the visitor's system setting. Headings use Bahnschrift, which ships with Windows; the hero's moving belts only run without reduced motion. |
| `img/` | The screenshots, generated by `pnpm site:screenshots` (below). Don't edit them by hand. |
| `favicon.svg`, `favicon.ico`, `apple-touch-icon.png` | Copies of the app icon (`design/icons/mainbus.svg`, `build/icon.ico`, `resources/icons/mainbus-256.png`). |
| `robots.txt` | Allows everything. |
| `CNAME` | `mainbus.app`, for GitHub Pages when it publishes from a branch. |

The whole folder is published as it is, this README included.

## Screenshots

```bash
pnpm site:screenshots
```

This builds the app, then runs it with the scripted fake runtime (FakeRuntime), a temporary data home and two throwaway git repositories made up for the demo: **acme-web**, a web shop, and **field-notes**, a notes app. A script (`scripts/site/screenshots.spec.ts`, with the board's tickets and agents in `scripts/site/demoSeed.ts`) plays a story on that board and captures each scene at 1440×900 at 2× in Light and Dark, and the board in Night Owl.

- It never opens your own board, data home or repositories, and calls no model.
- Before every capture, the temporary folder's paths are shown as `C:\Users\demo\...`, and the run fails if the page still shows this machine's home folder, user name, computer name, git identity or temporary folder.
- Each image is saved as a 2× and a 1× WebP per theme, with a 1× PNG fallback, plus `img/og.png` (1200×630) for social cards. Re-running replaces them. The raw captures are in `test-results/site-shots/`.
- The run fails if a WebP is over 500 KB or `img/` is over 12 MB, and prints every file's size.

Run it again when the app changes, check the pictures, and commit `site/img/`.

## Checks

```bash
pnpm site:check
```

- `scripts/site/checkLinks.mjs`: every local link, image and `srcset` exists, every `#fragment` has its target, every image has alt text, a width and a height, and there are no scripts. It lists the external links; `node scripts/site/checkLinks.mjs --external` also fetches them.
- `scripts/site/site.spec.ts`, in a hidden window of the repo's own Electron: axe with every rule (contrast included) on both pages in light and dark, every image loading, nothing overflowing sideways at 360, 768, 1024 and 1440 px, no motion with reduced motion on, the skip link and focus outlines, and the meta tags, icons, `og.png`, `robots.txt` and `CNAME`.

## Hosting on GitHub Pages

The repository is public on GitHub, so GitHub Pages is the simplest host. Two ways to publish:

**A. With the workflow (recommended).** `.github/workflows/site.yml` uploads `site/` and deploys it. It only runs when started by hand, so nothing is published by a push.

1. In the repository, open **Settings → Pages** and set **Source** to **GitHub Actions**.
2. Under **Custom domain**, enter `mainbus.app` and save. (With a workflow, GitHub ignores the `CNAME` file: the domain comes from this setting.)
3. Add the DNS records below and wait for the DNS check to pass.
4. Open **Actions → Publish mainbus.app → Run workflow**.
5. Once the certificate is issued, tick **Enforce HTTPS**.

To publish on every change to the site instead, add a push trigger to the workflow:

```yaml
on:
  workflow_dispatch:
  push:
    branches: [main]
    paths: ['site/**']
```

**B. From a branch.** GitHub Pages can only publish a branch's root or its `/docs` folder, not `/site`, so this needs the site copied to a branch of its own (for example `gh-pages`), where the `CNAME` file sets the domain. The workflow avoids that.

### DNS records for mainbus.app

At your domain's DNS provider, for the apex domain (`@`), from [GitHub's documentation](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site):

| Type | Name | Value |
|---|---|---|
| `A` | `@` | `185.199.108.153` |
| `A` | `@` | `185.199.109.153` |
| `A` | `@` | `185.199.110.153` |
| `A` | `@` | `185.199.111.153` |
| `AAAA` | `@` | `2606:50c0:8000::153` |
| `AAAA` | `@` | `2606:50c0:8001::153` |
| `AAAA` | `@` | `2606:50c0:8002::153` |
| `AAAA` | `@` | `2606:50c0:8003::153` |
| `CNAME` | `www` | `artjumble.github.io` |

- Remove any default `A` record your provider added.
- Don't add wildcard records (`*.mainbus.app`): they allow domain takeovers.
- Optionally, verify the domain for your GitHub account (**Settings → Pages → Add a domain** in your profile settings), which adds a `TXT` record named `_github-pages-challenge-artjumble`. A verified domain can't be claimed by another account's Pages site.
- Check the records with `dig mainbus.app +noall +answer` and `dig www.mainbus.app +noall +answer`.
- `.app` domains are on the HSTS preload list, so browsers only ever load them over HTTPS. The site won't open until GitHub has issued its certificate; then tick **Enforce HTTPS**.

## Other hosts

The site is a folder of static files, so any static host works. Both of these serve `404.html` for unknown paths.

- **Cloudflare Pages:** create a project from the GitHub repository with no framework preset, **no build command**, and **build output directory** `site`. Add `mainbus.app` under **Custom domains**; if the domain's DNS is on Cloudflare, it adds the records itself, otherwise point a `CNAME` at the project's `*.pages.dev` address as it shows.
- **Netlify:** create a site from the repository with **no build command** and **publish directory** `site` (or `netlify deploy --dir=site`). Add `mainbus.app` under **Domain management**, then either use Netlify DNS or add the `A` record (`@` to Netlify's load balancer address) and the `www` `CNAME` it shows you.

With either, the `CNAME` file and the GitHub workflow are unused, and can be left as they are.
