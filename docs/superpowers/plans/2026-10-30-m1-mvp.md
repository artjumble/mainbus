# M1 Self-Hosting MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The smallest Mainbus that can complete a real Mainbus ticket: one workspace, local tickets on a board, a worktree per ticket, and one Implementer agent whose thread streams live, with inline question and permission cards.

**Architecture:**
- An Electron app whose main process hosts a plain-Node **engine**: SQLite store, worktree manager, ticket runner, and an `AgentRuntime` adapter.
- The engine talks to a React + Mantine renderer over one typed IPC channel.
- Agents run through the TypeScript Agent SDK against the installed `claude.exe`.
- Agent state is always derived from the event log by `currentState`.

**Tech Stack:**
- Node 24, TypeScript 5 (strict).
- electron 45.2.0, electron-vite 6.0.0, electron-builder.
- react 19.3.1, @mantine/core and @mantine/hooks 9.7.4, @dnd-kit/core 6.3.1, react-markdown, zustand 5.0.16.
- **(M0)** SQLite through Node's built-in `node:sqlite` (`DatabaseSync`), wrapped by drizzle-orm 0.45.4's `sqlite-proxy` adapter and migrator, with drizzle-kit 0.31.11 for migrations. No native modules.
- @anthropic-ai/claude-agent-sdk 0.3.314, zod 4.6.7.
- vitest 5.0.5, @testing-library/react, jsdom, @playwright/test 1.64.1.

**Spec:** `docs/superpowers/specs/2026-10-30-mainbus-design.md`. Sections §5–§10 and §15a are the ones this plan implements.

**Prerequisite:** M0 is complete. `test/fixtures/sdk/*.jsonl` exists, and this plan has been amended by M0 Task 9.

## Global Constraints

- **Credentials:** only the official `claude.exe` is driven, passed as `pathToClaudeCodeExecutable`. Nothing reads `~/.claude/.credentials.json` or any token. `ANTHROPIC_API_KEY` is removed from the agent's environment.
- **Agents stay in their worktree:** agents never get `cwd` in the user's checkout. Every agent runs in its ticket's worktree.
- **Data home:** `MAINBUS_HOME`. The default is `%LOCALAPPDATA%\Mainbus` for the stable build and `%LOCALAPPDATA%\Mainbus-dev` for `npm run dev`. Off Windows it is `~/.mainbus` and `~/.mainbus-dev`.
- **Layout under the data home:**
  - database: `<home>\mainbus.db`
  - worktrees **(M0)**: `<home>\work\<workspace-slug>\<number>-<slug>`. The folder is named `work`, not `worktrees`, so path-based rules in a user's Claude config don't match it.
  - DB backups: `<home>\backups\`
- **Branches:** `mainbus/<number>-<slug>`. Slugs are lowercase ASCII `[a-z0-9-]`, at most 40 characters. A slug that is a Windows reserved name (`con`, `nul`, `prn`, `aux`, `com1`–`com9`, `lpt1`–`lpt9`) gets the suffix `-t`. An empty slug becomes `ticket`.
- **Board:**
  - Columns are fixed, in this order: Backlog, Ready, In progress, Needs you, Review, Done.
  - Phases shown in the MVP: Not started, Implementing, Waiting on you, Ready for review, Done.
  - Cards show only `#number`, title and the phase chip, plus a one-line summary in Needs you. Never model, effort, tokens or timers.
- **Naming:** work is named "<ticket title> is <phase>" and agents by role ("Implementer"). Never "Agent 1".
- **UI:** Mantine components only. No Tailwind. A CSS Module only where Mantine can't express the style. Send buttons sit inside the input box.
- **Disallowed agent tools (M0):** `AskUserQuestion`, `Agent`, `Task`, `EnterWorktree`, `ExitWorktree`, `CronCreate`, `CronDelete`, `CronList`, `ScheduleWakeup`, `ListAgents`, `TaskStop`.
- **Role tool names (M0):** `mcp__mainbus__ask_user` and `mcp__mainbus__handoff`, from an in-process SDK MCP server named `mainbus`.
- **Agent setting sources (M0):** `settingSources: ['project', 'local']`. Agents never load the user's global Claude settings, hooks, plugins or memory.
- **Permissions (M0):** `permissionMode: 'auto'` plus the Mainbus guard (Task 8a). Mainbus never returns `updatedPermissions` to the SDK, because that writes `.claude/settings.local.json` into the worktree.
- **Git calls (M0):** success is decided by exit code only (git writes progress to stderr). Pass `-c core.longpaths=true`.
- **Permission choices:** Allow once, Always allow in this workspace, Deny.
- **Windows:** spawn processes without a shell (`execFile`, never `exec`), with `windowsHide: true`. Parse output line by line, tolerating CRLF.
- **Single instance:** a second launch focuses the existing window.

## Review Focus

1. A repo path with spaces and non-ASCII characters (`C:\Users\<user>\My Projects\café`) works: the worktree is created, the agent starts and commits. Test owner: Task 6.
2. If `claude.exe` is missing or not logged in, Mainbus shows a setup screen saying which, rather than crashing or showing a blank board. Test owners: Task 10 and Task 13.
3. If Mainbus is quit while an agent waits on a permission, the ticket reopens Paused with Continue. The stale permission card shows as expired, not answerable. Test owner: Task 11.
4. A message typed while the agent is mid-turn is delivered, not dropped, and appears in the thread immediately. Test owner: Task 11.
5. A ticket title that's all emoji or a reserved word ("🔥🔥", "CON") still gets a valid branch and folder. Test owner: Task 6.
